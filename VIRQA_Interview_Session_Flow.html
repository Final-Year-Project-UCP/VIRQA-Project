Live Interview Session & AI Pipeline

Complete Technical Lifecycle & Evaluation Flow

Socket.io WS Channels Groq Whisper large-v3 Groq llama-3.1-8b-instant Real-Time boundary TTS Sync

This document provides the exhaustive technical reference for the real-time AI interview interaction loop. It details how voice audio is streamed to the backend, transcribed via Whisper, evaluated by Llama-3 in the background, and how the dynamic next question is generated and spoken back to the candidate with real-time text-to-speech visual synchronization.

1 Live Session Sequence Flow

The candidate interacts with the AI Interviewer over a real-time bi-directional WebSocket connection. The sequence diagram below displays the event loops during a single Q&A cycle. 

sequenceDiagram

    actor Candidate as Candidate (Frontend)

    participant Backend as Node.js Backend
    participant Whisper as Groq Whisper STT
    participant LLM as Groq Llama-3.1 LLM
    database DB as MongoDB

    Note over Candidate: Candidate starts recording response
    Candidate->>Socket: emit("send-audio", { audioBuffer, currentQuestionText })
    Socket->>Backend: Receive Binary ArrayBuffer
    Backend->>Candidate: emit("processing-status", "Transcribing...")
    
    Note over Backend: Audio Conversion & Transcription
    Backend->>Whisper: POST /transcriptions (transient webm stream)
    Whisper-->>Backend: Return transcribed text string
    Backend->>Candidate: emit("transcription-result", { transcribedText })
    
    Note over Backend: Asynchronous Scoring starts in background
    Backend->>LLM: evaluateAnswer(question, transcription)
    Backend->>Candidate: emit("processing-status", "Evaluating...")

        Backend->>LLM: streamInterviewerReply(chatHistory, currentDifficulty)
        LLM-->>Backend: Stream reply tokens

        LLM-->>Backend: JSON scores
        Backend->>DB: Push answer & evaluation to AIInterview Document
        Backend->>Candidate: emit("evaluation-result", { evaluation })
    end

    Note over Candidate: speechSynthesis plays audio & reveals text

2 Audio & Evaluation Pipeline

When the candidate submits a voice answer, it passes sequentially through transcription (STT) and AI Evaluation services. Below is the technical state changes flow: 

flowchart TD
    A([🎙️ Candidate finishes speaking]) --> B["Capture webm ArrayBuffer (Client)"]
    B --> C["emit send-audio (WS)"]
    C --> D["emit processing-status 'Transcribing...'"]
    D --> E["Write buffer to transient file audio-{timestamp}.webm (Server)"]
    E --> F["Groq Whisper API whisper-large-v3"]
    F --> G["Delete temp file (finally block)"]
    G --> H["emit transcription-result transcribedText"]
    H --> I["Push to AIInterview.answers[] in database"]
    I --> J["emit processing-status 'Evaluating...'"]
    J --> K["Background evaluateAnswer (Groq Llama-3.1)"]
    K --> L["Output: JSON evaluation metrics"]
    L --> M["Push to AIInterview.scores[] in database"]
    L --> N["emit evaluation-result evaluation JSON"]
    L --> O["Run adjustDifficulty() engine"]
    O --> P(["Update currentDifficulty for next Question"])

3 TTS Word-by-Word Synchronization

The candidate expects text to reveal on the screen synchronously as the AI voices the question. This is achieved via client-side Speech Synthesis events: 

sequenceDiagram
    autonumber
    participant Server as Socket Server
    participant Client as Candidate Client (ActiveSession.jsx)
    participant Speech as window.speechSynthesis (Web API)
    participant UI as Chat Thread UI

    Server->>Client: emit("ai-response-chunk", { chunk })
    Note over Client: Displays blinking typing bubble in bubble block
    Server->>Client: emit("ai-response-complete", { questionText })
    Client->>Client: Create SpeechSynthesisUtterance(questionText)
    Client->>Speech: window.speechSynthesis.speak(utterance)

    alt Speech Synthesis starts
        Speech->>Client: utterance.onstart() event
        Client->>UI: Remove typing bubble, set chat text to ""
        loop On Boundary Word Event
            Speech->>Client: utterance.onboundary(event) [event.name === 'word']
            Client->>Client: Find charIndex & next whitespace index
            Client->>Client: Slice text: questionText.substring(0, nextSpace)
            Client->>UI: Update AI bubble text progressively (displays word-by-word)
        end
        Speech->>Client: utterance.onend() event
        Client->>UI: Render full text, display answer countdown & start recording
    else Fallback Trigger (speech synthesis blocked/fails to start within 1.5s)
        Note over Client: Fallback timer setTimeout finishes
        Client->>UI: Display full questionText immediately, start recording
    end

4 End-of-Interview Report Logic

When the interview is completed (by the candidate ending the session or time limits), the system processes scores and generates final recommendation reports. 

flowchart TD
    A([👤 Candidate Ends Session / Time Up]) --> B["Exit fullscreen mode"]
    B --> C["emit 'interview-complete'"]
    C --> D["Backend: Find AIInterview & calculate scores"]
    
    D --> E["🧮 Calculate Penalty Divisor
    divisor = max(actualQuestionsCount, minExpectedQuestions)"]
    E --> F["*minExpectedQuestions = max(5, min(10, duration / 6))"]
    
    F --> G["Aggregate metrics:
    overallScore = sum(overall) / divisor
    semanticScore = sum(semantic) / divisor
    technicalScore = sum(technical) / divisor"]
    
    G --> H{overallScore > 70%?}
    H -->|Yes| I["Recommended Verdict
    finalReport: 'Highly recommended for next rounds'"]
    H -->|No| J["Review Verdict
    finalReport: 'Requires technical improvements'"]
    
    I --> K["Save finalReport & status = 'completed'"]
    J --> K
    K --> L["Update parent InterviewSession candidate status to Completed"]
    L --> M["emit 'interview-completed-successfully'"]
    M --> N(["Candidate redirected to Results Page Radar Chart"])

6 Scoring Formulas Reference

Formulas used by the system to compile scores fairly and handle early exit cheats.

Score Type Formula Description
Minimum Expected Questions $$\max\left(5, \min\left(10, \text{round}\left(\frac{\text{Duration}}{6}\right)\right)\right)$$ Computes minimum required questions for a session (e.g. 5 questions for 30 minutes).
Penalized Divisor $$\text{Divisor} = \max(\text{Questions Answered}, \text{Expected Questions})$$ Ensures that candidates who exit early get penalized for leaving unanswered questions blank.
Overall Score $$\text{Score} = \text{round}\left( \frac{\sum \text{overallScore}_{\text{questions}}}{\text{Divisor}} \right)$$ Averages evaluated questions against the penalized divisor.
Completeness Metric $$\max(0, \text{Overall Score} - 5)$$ Deducts 5 points from the overall score to compile the report visual map.
Confidence Metric $$\max(0, \text{Overall Score} - 3)$$ Deducts 3 points from the overall score to reflect conversational confidence.
